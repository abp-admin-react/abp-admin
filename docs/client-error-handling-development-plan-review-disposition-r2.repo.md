## 核实结论

分别核对三份报告、本地实际源码和ABP10.7.0固定标签，再合并有冲突的建议。下面共R2G01—28、R2H01—35、R2Q01—27，90个追踪项包含重复与正面确认，不是90个缺陷。报告行号保留原文件位置；v1.1方案/第一轮处置引用是修订前历史位置，执行定位以v1.2章节为准。上游行号以原始文件计数，不使用网页抽取后压缩行号。

主要吸收：

- 原协议端点未捕获异常仍须安全兜底，补/connect、/v1流前/流后及Hub握手用例；保持正常协议重定向与错误形状。
- 关联号具体服务替换与头写出责任；外部入口统一服务端主关联号，不按尚未认证的管理身份信任传入值。
- HTTP401首期只允许Client:AuthenticationRequired或无码；其他码与文案丢弃，503图片繁忙固定目录映射为Unexpected/server。
- 管理Data按出口批准集合验收，补OAuth原文来源、显式空体结果与写出候选漂移门禁。
- 测试改为专用HTTP工程＋现有dotnet test独立进程：P1 Development基线，P4发布前Production及完整CI；不新建通用父子进程runner。
- 明确catalog结构版本、快照更新变量、资源缺键/运行态贡献者负例和复核命令；版本化文档及标准仓库链接进入实施交付条件。

上一轮处置有真实错误：H05/H07/H08/H10/H11/H12/H37等将带条件或未提出的方案写成拒绝对象，Q20又误写了快照变量。这些已直接更正。H01明确区分“特定异常必经Friendly”的过强链路推断与成立的默认Data/message风险，避免让限定链路的结论否定风险本身。
