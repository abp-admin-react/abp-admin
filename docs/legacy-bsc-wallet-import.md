# 迁移 Exchange 的 BSC 充值钱包

旧 Exchange 的「收款配置 → BSC → 充值总密钥 → 补全历史用户充值地址」使用已有总密钥给缺地址的用户批量派生。迁移时在新后台使用「交易运营 → 链上充提 → 链上运维 → 链上钱包 → 迁移旧充值钱包」。

1. 在目标后台初始化链上凭据加密密钥，关闭扫链和归集。首次导入要求目标钱包尚无总密钥、地址、归集记录或扫链游标。
2. 建立旧用户与目标宿主用户 UUID 的映射。从旧库导出 BSC 已分配地址，保留地址、派生索引、活跃或停用状态，以及包括停用记录在内的历史最大已分配索引。活跃地址的 `userId` 填目标用户 UUID。停用地址可填 `null`。页面内有 JSON 格式示例。上次演练的匿名地址只用于对账。
3. 上传地址清单，在遮罩输入框单独输入线下备份的原助记词。系统逐条重推地址，对应一致后才提交，并以新后台加密格式保存总密钥。提交完成会显示活跃地址数、停用地址数与下一可分配索引。同一清单和助记词可安全重试。
4. 核对新后台返回的索引，旧充值地址的派生路径为 `m/44'/60'/0'/0/i`，索引 1 沿用原助记词派生的 Gas 地址。生产接管前按已复核的截止点交接代币扫链游标、回看缺口和资金账本。导入不启动后台任务。迁移过的钱包在游标为空时跳过扫描，避免从当前链头漏掉旧充值。

在全新的隔离环境测试新用户派生时，可使用「生成充值总密钥」配置一个独立钱包。扫链和金库配置就绪后，用户首次领取充值地址会分配新索引。迁移完成后的同一网络会拒绝生成新的总密钥。
