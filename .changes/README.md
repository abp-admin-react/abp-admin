# `.changes/` — 框架底座升级说明约定

本目录是**面向派生项目交付升级**的结构化变更说明(替代自由文本 changelog)。派生项目跟随本仓库合并时,按最新的 `Migration X.Y.Z - X.Y.W.md` 逐项执行即可完成升级。

## 约定

1. **发布时命名**:`Migration {旧版本} - {新版本}.md`(版本号取 `backend/common.props` 的 `<Version>`)。发布前,`Unreleased.md` 的内容整理进新的 Migration 文档并清空。
2. **未发布变更**随手记在 `Unreleased.md`,按下面模板的四个章节累加,不追求行文,只要求信息全。
3. **四个章节缺一不可**(没有就写"无"):
   - **模块变更**:按模块/项目前缀列出行为变化,派生项目据此判断自己的业务模块是否受影响;
   - **依赖项变更**:库名 | 原版本 | 现版本 三列表;只有在本仓库 `Directory.Packages.props` 主动调整的才记录,传递升级不用记;
   - **数据库迁移**:`项目 | 迁移/脚本 | 说明` 三列表——与迁移机制(框架库 EF 迁移走 `__EFMigrationsHistory`,业务模块各自的 History 表)对齐,派生项目照表核对自己的库;
   - **配置变更**:appsettings 新增/删除/改名的键,给出默认值与是否必填。派生项目合并后"启动即炸"的问题 90% 出在这一节,宁可啰嗦不可省略。
4. **破坏性变更**在条目前加 `**[破坏性]**` 前缀,并写明迁移动作。
